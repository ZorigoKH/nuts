# Generated data

Both files here are generated by the tools in `tools/` and committed so that nobody has to
regenerate them. Regenerating gives byte-for-byte the same files.

| file | made by | contents |
|---|---|---|
| `equity169.bin` | `tools/gen_equity169.cpp` | exact 169 x 169 preflop equity matrix (228,504 bytes) |
| `equity169.sha256` | `shasum -a 256` | its SHA-256 |
| `pushfold.json` | `tools/gen_pushfold.cpp` | heads-up push/fold equilibrium for S = 1.0, 1.5, ..., 20.0 bb |

`equity169.bin` is also compiled into the Python module and the WebAssembly build (CMake turns
it into a C++ array; see `include/nuts/embedded_data.hpp`), which solve push/fold on request. A
C++ test checks that the compiled-in copy is byte-for-byte this file.

## Regenerating

From the repository root, after a Release build (`cmake -S . -B build -G Ninja && cmake --build build`):

```sh
./build/nuts_gen_equity169 data/equity169.bin
(cd data && shasum -a 256 equity169.bin > equity169.sha256)
./build/nuts_gen_pushfold data/equity169.bin data/pushfold.json
```

To check the committed matrix without replacing it:

```sh
(cd data && shasum -a 256 -c equity169.sha256)
./build/nuts_gen_equity169 /tmp/equity169.bin && cmp /tmp/equity169.bin data/equity169.bin
```

`nuts_gen_equity169` enumerates every board for each of the 47,008 heads-up matchups that are
different up to suit renaming: 47,008 x C(48, 5) = 80.5 billion showdowns. Measured twice on an
Apple M3 (8 hardware threads, Release, `-O3 -DNDEBUG`, Apple clang 21), both times with another
heavy job running:

| run | load average at start / end | wall clock | CPU time |
|---|---|---|---|
| 1 (made the committed file) | 4.9 / 74 | **390 s (6.5 min)** | 2,441 s |
| 2 (to a scratch file) | 9.2 / 33 | **363 s (6.0 min)** | 2,390 s |

Run 2's output was byte-for-byte identical to the committed `equity169.bin`. The result does not
depend on the number of threads (`--threads N`, 1 to 256).

The tests check both files: `tests/python/test_data_files.py` that `equity169.bin` matches
`equity169.sha256`, a C++ test that the copy compiled into the libraries is byte-for-byte
`equity169.bin`, and a Python test that `pushfold.json` matches fresh solves at a few stacks.

`nuts_gen_pushfold` takes 0.3 s for all 39 stacks on the same machine.

## `equity169.bin` format

All integers are unsigned 32-bit little-endian.

| offset | size | contents |
|---|---|---|
| 0 | 8 | the characters `NUTSE169` |
| 8 | 4 | number of hand classes: 169 |
| 12 | 4 | boards per matchup: 1,712,304 = C(48, 5) |
| 16 | 169 x 169 x 4 | `weight[i][j]`, row by row |
| 114,260 | 169 x 169 x 4 | `half_pots[i][j]`, row by row |

Hand class `i` is cell `i` of the usual 13 x 13 chart: `i = 13 * row + column`, rows and columns
in the order A, K, ..., 2, pairs on the diagonal, suited hands above it (`AKs` = 1) and offsuit
hands below it (`AKo` = 13).

- `weight[i][j]`: the number of pairs (hand of class i, hand of class j) with no card in common.
- `half_pots[i][j]`: over those pairs and all their boards, the half pots won by the class-i
  hand: 2 per win, 1 per tie.
- The equity of class i against class j is `half_pots[i][j] / (2 * 1,712,304 * weight[i][j])`.

The loader (`nuts::load_equity169`) checks that the weights are symmetric, that each row of
weights adds up to (hands in the class) x 1,225, and that `half_pots[i][j] + half_pots[j][i]`
is exactly 2 x 1,712,304 x `weight[i][j]` (the two equities add up to 1).

## `pushfold.json` format

- `game`, `solver`, `exploitability`: what was solved and how (see `include/nuts/pushfold.hpp`).
- `grid.hands`: the 13 x 13 hand names, in the same layout as the strategy grids.
- `solutions`: one entry per stack, with `stack_bb`, CFR+ `iterations`, `exploitability_bb`,
  the SB's expected result `sb_ev_bb`, the share of all 1,326 hands shoved and called
  (`shove_percent`, `call_percent`), and the 13 x 13 grids `shove` (probability that the small
  blind goes all-in) and `call` (probability that the big blind calls an all-in).

Probabilities are rounded to 6 decimals, and `exploitability_bb` is computed for the rounded
strategies as written. The largest is 1.34e-6 bb per hand (at 14.0 bb).
